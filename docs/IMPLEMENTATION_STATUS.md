# Состояние реализации

Текущий релиз: [Version 16.1](https://github.com/KirillBass/WIFI_Scanner/releases/tag/v16.1.0).
Приложение работает на Windows 10/11 x64. Интерфейс построен на Avalonia, графики на ScottPlot, логика написана на C# и .NET 10.

## Сканирование Wi-Fi

Windows Native Wi-Fi API получает доступные BSS. В «Эфире» показаны SSID, MAC-адрес точки доступа, RSSI, канал, диапазон, частота и время обнаружения. Таблица и три варианта фильтра включают только 2,4/5 ГГц; счётчик полного результата закреплён под таблицей и не зависит от фильтрации. Доступны поиск и сортировка по сигналу. Одинаковые SSID с разными BSSID остаются отдельными точками; внутренние идентификаторы сохранены.

Вендор определяется по встроенной OUI-базе. Стандарт и объявленная защита определяются по Native PHY и Information Elements: 802.11a/b/g/n/ac/ax/be, Wi-Fi 4/5/6/6E/7, Open/WEP/WPA/WPA2/WPA3, Personal/Enterprise, transition и OWE. Шифры и PMF доступны в подробностях. Неизвестные данные не подменяются догадками.

Подробности: [расширение «Эфира»](AIR_CAPABILITIES_REPORT.md).

## Мониторинг сигнала

Мониторинг выбранного BSSID поддерживает интервалы 1, 5, 10, 15, 30 и 60 секунд после завершения предыдущего сканирования. Циклы не перекрываются; устаревшее время измерения Native Wi-Fi не создаёт повторную точку RSSI. Хранятся последние 300 измерений, текущий, средний, минимальный и максимальный RSSI. История остаётся после остановки и очищается кнопкой «Очистить». Переход между вкладками не прерывает мониторинг.

## Анализ каналов

Для диапазонов 2,4 и 5 ГГц доступны график частотного перекрытия, сводка с числом точек и предпочтительным каналом и короткий **Результат анализа**. Ось графика подписана номерами каналов, а частота в МГц доступна при наведении на кривую. Все значения соответствуют выбранному диапазону и последнему снимку. Если данных для рекомендации недостаточно, вкладка сообщает об этом. Для оценки используются RSSI и расстояние между частотами, а ширина 20 МГц служит параметром модели. Фактическая загрузка эфира не измеряется.

## Устройства локальной сети

Для выбранного Wi-Fi или Ethernet интерфейса отображаются IPv4, подсеть и шлюз. Обнаружение объединяет ICMP и таблицу соседей Windows, ограничивается выбранным интерфейсом; адреса подсети обрабатываются потоково, без прежнего предела 1024 адреса. Состояния Online/Unknown/Offline, FirstSeen/LastSeen и история сохраняются между циклами; мониторинг имеет интервалы 1/5/10/30/60/120 секунд после завершения предыдущего цикла.

IP и MAC появляются до завершения идентификации. Имя и производитель обновляются асинхронно через LocalComputer, локальный Reverse DNS, mDNS/DNS-SD, NetBIOS, LLMNR, SSDP/UPnP и встроенную OUI-базу. Идентификация не меняет историю присутствия устройства.

В Version 8 добавлены кнопка «Обновить имена», короткий отрицательный кэш, дополнительные mDNS-запросы и прямой mDNS PTR через выбранный интерфейс. Можно сразу начать через Wi-Fi. Ранее полученное имя переносится между Wi-Fi и Ethernet только при совпадении подтверждённой сети, шлюза и MAC устройства. Подсказка показывает источник, интерфейс и время получения имени.

Подробности: [Device Identity](DEVICE_IDENTITY_REPORT.md).

## Подключение и сетевая сессия

Из «Эфира» доступны подключение к Open/WPA2-Personal и выбор адаптера. Для WPA2 требуется известный пароль и поддержка CCMP. Смешанное объявление TKIP+CCMP и групповой TKIP не блокируют подключение с AES/CCMP. Используются временный профиль, уведомления Windows и отдельное ожидание IPv4.

Общая сессия содержит SSID, фактический BSSID, адаптер, IPv4, подсеть и шлюз. После готовности IPv4 текущая вкладка сохраняется; для доступа к аудиту нужно успешно завершить поиск в «Устройствах». Пароль не сохраняется в настройках или журналах. Отключение и смена сети отменяют операции прежней сессии.

Подробности: [Wi-Fi Connection](WIFI_CONNECTION_REPORT.md).

## Аудит TCP-портов и служб

Аудит запускается для снимка найденных устройств текущей сессии и шлюза. Доступны профили «Быстрый» (7 целевых портов), «Стандартный», «Полный» и «Пользовательский», прежние значения параллелизма и тайм-аута без ручных полей в интерфейсе. Быстрый/стандартный включают собственный ПК всегда, пользовательский по флажку, полный по сохранённой настройке. «Параметры» активны только для пользовательского профиля и содержат пользовательские порты и включение ПК. Используется TCP Connect с привязкой к выбранному интерфейсу.

Открытые порты появляются сразу, затем асинхронно уточняются служба, продукт, версия, достоверность и доказательство определения. HTTP/HTTPS, SSH, FTP, RDP и SMB распознаются по ответам сервера. Неизвестная служба остаётся Unknown; номер порта сам по себе не подтверждает протокол. Подтверждённые сайты с успешной страницей выделены светло-зелёным и подняты в верхнюю группу. Компактные подробности содержат сведения службы, открытие сайта и фактический HTTP-запрос/ответ, без вложенных таблиц и дополнительных сетевых запросов. Чувствительные заголовки и query-параметры скрыты. Для SMB и FTP справа доступен просмотр метаданных каталога по явному действию пользователя. Панель SMB открывается при выборе подтверждённой службы. По запросу для выбранного сервера системный клиент Windows возвращает видимые файловые ресурсы через `NetShareEnum`, а панель хранит список в пределах текущего аудита и проверяет доступ при открытии папки. FTP использует FluentFTP и фактический порт. Для SMB подтверждённый диалект отображается по результату NEGOTIATE. Ввод учётных данных ограничен выбранным ресурсом, пароль хранится только в памяти открытой панели.

При отключении или смене сети аудит отменяется, результаты прежней сессии очищаются. Закрытие приложения ожидает завершения фоновых операций.

Подробности: [Network Audit](NETWORK_AUDIT_REPORT.md).

## Структура и ограничения

Solution содержит три проекта: Core с моделями и алгоритмами, Infrastructure.Windows с Windows API и сетевыми сервисами, App с Avalonia, MVVM и DI. Общие сервисы сканирования, мониторинга и сетевой сессии используются всеми страницами. Новые возможности встроены в существующие проекты.

Данные обрабатываются локально. Внешние API идентификации MAC/IP/hostname не используются. Имя доступно только если устройство или локальная сеть публикует его. Private MAC, сон, firewall, VLAN и Client Isolation ограничивают обнаружение и идентификацию. Тайм-аут TCP не означает закрытый порт. Общий аудит подтверждает службы. Вход в каталог SMB или FTP запускается отдельным действием пользователя. В текущем этапе реализован TCP; UDP-аудит и IPv6 не включены.

## Текущая компоновка интерфейса

Шесть вкладок: Эфир, Каналы, Сигнал, Устройства, Сетевой аудит, Настройки. По умолчанию открываются «Устройства»; автоматического сканирования нет. «Каналы» и «Сигнал» доступны после пригодного результата эфира, «Сетевой аудит» после успешно завершённого поиска устройств актуальной сети, включая пустой результат. Во время нового поиска, после ошибки/отмены или смены сети аудит недоступен; причина показана в tooltip отключённой вкладки. Заблокированная стартовая вкладка заменяется «Устройствами». Успешный поиск не переключает страницу автоматически.

Сведения о службе и HTTP-обмен находятся в адаптивной панели. Лишние команды обычного аудита, дополнительных портов и всех портов узла убраны из UI; низкоуровневый код сохранён. Отключение Wi-Fi доступно в «Эфире». Пользовательские настройки включают стартовую вкладку, запоминание интерфейса, собственный ПК, компактные строки и прежний выбор каталога журналов. Настройка профиля по умолчанию удалена, старое поле JSON игнорируется.
